# blockporter

直接改 Minecraft Java 版存档（`.mca`）的命令行工具。不依赖 Amulet，也不用启动游戏。用来把旧版本里玩家改过的方块搬进新版本的空板，再把搬完之后对不上的方块、索引和残块清掉。

项目分两块：

| | 是什么 | 编出来是什么 |
|---|---|---|
| **nbtrw** | 读写 NBT、区块、区域文件、整个存档的库 | `libnbtrw.so`，以及一个只读 demo `nbtrw` |
| **blockporter** | 搬图和修图 | `merge`、`fixer`、规则插件 `rules.so` |

规则插件按 **Java Edition 26.1.1（DataVersion 4788）** 写。`fixer` 要求存档的 DataVersion 和插件完全一致，否则拒绝动手。

> **先看这几句**
>
> 本仓库**大量代码由 AI 生成，人类只审核了逻辑结构，没有逐行审过实现**。它还在测试，不保证结果正确，作者不对数据丢失、存档损坏、进度异常负责。
>
> `merge` 和 `fixer` **就地改目录，没有试运行**。先把整个存档拷走，只在副本上跑。`new`（输出）和 `now`（游玩图）不能是同一个目录。

库接口说明在 [ReadMe.md](ReadMe.md)；改代码看 [ReadMeDeveloper.md](ReadMeDeveloper.md)。DEV 里分成“现行规范”和“历史踩坑”，标了历史的段落不要当现行行为；命令行行为以本文件、`merge.cpp` / `fixer.cpp` 开头注释和实际代码为准。

## 和上一版的差别

如果你用过带 `prune` 的那一版，这几条是断掉的，别按旧文档跑：

- **`prune` 删了**，删残块、删空区域文件、整理区域文件都进了 `fixer`。
- **`make` 不再编 merge / fixer**。只要库和 demo 用 `make`；要搬图修图用 `make blockporter`。
- 库从 `libnbt.so` 改名 **`libnbtrw.so`**，头文件是 `nbtrw.hpp`。
- **`merge` 的 `old` 给空串 `""` 不再是“只统计”**。没有旧板时，它会拿 `now` 和 `new` 比，不一样就写入。
- `merge` 不再要求“至少有一个 old 里有这块”才动手，也不再改光照和高度图，也不再清掉跳过区块的 `InhabitedTime`。
- 计划刻、`poi/`、`entities/` 是**追加**进 `new` 的，允许和原来的记录重复。对不上、重复，留给后面的 `fixer`。
- `fixer` 会删 **`InhabitedTime` 为 0** 的整块（见下面的警告），不只是空壳。

## 建议怎么跑

目标版本用现在这套规则的话，就是 **26.1.1**。

1. 备份。下面全部只碰副本。
2. 用游戏自己的 **优化世界（Optimize World）** 把游玩图和旧空板升到 26.1.1。`merge` 不升级方块数据，它是按名字原样搬的。
3. 用 26.1.1 准备一份新空板（`new`）。这是输出，会被改写。种子、出生点、玩家数据都留在 `now` 里，本工具不搬 `level.dat` 里的这些字段，也不搬 `playerdata/`、`advancements/`、`stats/`。
4. `merge`：把 `now` 里相对旧板改过的方块搬进 `new`。
5. `fixer`：按规则拆掉撑不住的方块，并做下面说的清理。
6. 再进一次游戏或再跑一次优化世界，让游戏把被删掉的光照和高度图补回来。

**顺序只能是 merge → fixer，而且只走一趟。** `fixer` 拆掉或换成水的方块，在 `now` 里还是原样；再跑 `merge` 会把它们搬回来。

`merge` 会把每个处理过的区块的 `InhabitedTime` 改成“这一趟搬了几个方块”。一个方块都没搬就是 0。紧接着的 `fixer` 在范围盖住整块时，会把 `InhabitedTime` **明确为 Long 0** 的区块整块删掉（里面的新地形也一起没）；**缺少这个字段只补写成 0，不会因为“缺失”本身删块**。不想让没改过的地形被删掉，就不要用一份盖满全高的范围去跑 `fixer`，或者跑之前确认你接受“没住过的区块交给游戏按种子重生成”。

## 编译

需要 `g++`（C++23）、`zlib`、`libdl`。程序用 `-Wl,-rpath,'$ORIGIN'` 找同目录的 `libnbtrw.so`，整个目录拷走就能跑。

```sh
make              # 只要 libnbtrw.so 和 nbtrw
make blockporter  # 再编 rules.so.26.1.1、rules.so、merge、fixer
make rules        # 只重编规则插件
make clean
```

`fixer` 启动时先找自己旁边的 `rules.so`，没有再找当前目录。`rules.so` 是指向 `rules.so.26.1.1` 的符号链接。

## merge：把改过的方块搬过去

```sh
./merge <new> <now> <old[,old...]> <x1> <y1> <z1> <x2> <y2> <z2> <chunkunit> [dims]
```

| 参数 | 说明 |
|---|---|
| `new` | 新版本空板，**输出，会被改写**。目录里要有读得懂的 `level.dat` |
| `now` | 要升级的游玩图，只读 |
| `old` | 旧版本空板，只读。多个用逗号隔开。一个都没有就写 `""` |
| 六个坐标 | 方块范围的两个角，谁大谁小都行，**两头都包含**。必须是 int32 整数，写错直接退出 |
| `chunkunit` | `1`：x/z 向外对齐到区块边界，碰到的区块整块处理。`0`：严格按给定范围，范围外只读不写。只认 0 或 1 |
| `dims` | 可选。逗号隔开，默认 `minecraft:overworld`。原版三个维度写 `overworld`、`the_nether`、`the_end` 即可（可加 `minecraft:`）。其它字符串当成相对存档根的维度目录 |

```sh
# 主世界，整区块。有一块旧空板
./merge ./new ./now ./old -1000 -64 -1000 1000 319 1000 1

# 没有旧空板：now 和 new 不同的方块都会搬（这是写入，不是预览）
./merge ./new ./now "" -1000 -64 -1000 1000 319 1000 1

# 三个维度，两块旧空板
./merge ./new ./now ./old1,./old2 -1000 -64 -1000 1000 319 1000 1 \
        overworld,the_nether,the_end
```

每一格的判断：

- `now` 和 **任意一个** `old` 相同，或者和 `new` 自己相同：留 `new` 的。
- 否则算玩家改过，把 `now` 的方块写进 `new`。
- 比较包含方块实体。箱子里的东西、告示牌上的字变了，也算改过，会跟着方块一起搬。
- 没有 `old`（参数是 `""`）时，只和 `new` 比。某个 `old` 读不出来就忽略那一个，不因此整趟失败。

一块地要 **`now` 和 `new` 都有、`Status` 都是 `minecraft:full`、区块坐标（`xPos`/`zPos`）也对得上、区块结构没有坏到读不出来** 才会处理。对不上或读不出来就跳过这一块，不新建区块。只有真的要往 `new` 写方块时，缺的 section 才补一段空气（生物群系尽量从 `now` 抄）；整块没改动就不补。

处理过的区块还会：

- 把 `now` 里落在范围内的 `block_ticks` / `fluid_ticks` **追加**到 `new`（不去重）；
- 把对应的实体区块、POI 记录 **追加**到 `new`（不去重，票数原样）；
- 如果 `now` 有 POI/实体而 `new` 没有对应的 `.mca` 文件，会为已经处理到的区块新建
  `poi/` 或 `entities/` 文件；**不会新建 region 文件/区块**；
- `new` 里对应的 POI/实体块如果读不出来（LZ4/未知压缩、坏 NBT 等），只跳过这一块，绝不当成“没有这块”去新建/覆盖；`now` 源块读不出来也一样跳过；
- 把 `InhabitedTime` **覆盖**成这一趟搬过去的方块数（写成空气也算一次）。

不删光照，不删高度图，不整理重复的 section，不清空文件。这些是 `fixer` 的事。读不出来的区域文件不写也不删。终端是 tty 时，merge 会在 stderr 画区块进度条。

逐格比较用 `get_BlockRef` + `block_Ref_Equal` 的零拷贝路径，比较语义和 `get_Block` 的
`Block` 相等完全一致；只有确定要写的格子才构造 `Block`、才碰调色板。输出内容不变，
只省掉每格两份深拷贝和重复哈希。

## fixer：拆掉不该留的，并清掉残块和坏索引

```sh
./fixer <path> <x1> <y1> <z1> <x2> <y2> <z2> <chunkunit> [dims]
```

参数和 `merge` 的范围、`chunkunit`、`dims` 同一个意思。`path` 既是输入也是输出。没有试运行：要先看结果，就复制一份存档再跑。

```sh
./fixer ./new -1000 -64 -1000 1000 319 1000 1
./fixer ./new -1000 -64 -1000 1000 319 1000 1 the_nether,the_end
```

启动时会核对 `rules.so` 的 DataVersion 和 `level.dat`。对不上就什么都不改、直接退出。

它按这个顺序做：

1. **规则。** 逐格问 `rules.so`。撑不住的拆掉，或改状态（例如藤蔓关掉贴不住的那一面）。普通方块换成空气；只要结果是水（原方块含水、霜冰化水、规则 `FX_SET` 成水都算），就写水源并补一条 `fluid_ticks(i=minecraft:water, t=5, p=0)`，和游戏自己拆含水方块一样，避免在水里留洞。每次写方块前会先删这一格旧的 `block_ticks` / `fluid_ticks`。不改 `InhabitedTime`。连锁只看六个面。
2. **删区块 / 修子区块。**
   - `Status` 不是 `minecraft:full`（没有 `Status` 也算）：这一块删掉。x/z 只要沾到范围就整块删，不管 y 是否盖全。
   - 整块的 x/z **以及每一段的 y** 都在范围内，并且（里面没有非空气方块，**或者** `InhabitedTime` 明确是 Long 0）：整块删掉。**缺 `InhabitedTime` 字段写 Long 0，但不因此删块。**
   - NBT/结构坏到修不了的区块（压缩或 NBT 解析失败、`sections`/`block_states`/palette/data 容器/方块实体表容器形状不对）：整块删掉，并把 `entities/`、`poi/` 里同一格一起删。
   - **Y 缺失/不是 Byte 的子区块只删这一子区块**，不删整个区块；单条计划刻缺字段、单条 POI/实体记录缺字段也只删那一条（见下）。
3. **坐标、重复段、调色板。** `xPos` / `zPos` 按文件里的位置重写。同一个 Y 有多段 section 时只留最前面那段。`format_Chunk` 还会把 palette 里没被 `data` 引用的条目压紧，并重写 4096 个下标。
4. **光照和高度图。** 选中的区块删掉 `Heightmaps`，并删 `BlockLight` / `SkyLight`、把 `isLightOn` 写成 0。周围一圈（3×3，**含范围外的邻居**）只做光照删除；不再改范围外邻居的坐标或重复段。进游戏后由游戏重算。
5. **计划刻。** `block_ticks` / `fluid_ticks` 先删“缺字段/类型不对”的单条记录，再删“指向的方块和记录类型对不上”的记录；删完同一位置还有多条合法记录时只留一条：**`p` 最小优先，`p` 相同取 `t` 最大**。`block_ticks` 和 `fluid_ticks` 分开算，范围外不动。
6. **POI。** 按 `rules.so` 的方块→默认 POI 表校验：单条记录缺 `pos`/`type`/`free_tickets` 只删这一条；类型/票数对不上、方块已不该有 POI 的记录删掉；同一位置重复只留 `free_tickets` 最小的一条；缺失的按表补一条默认记录（例如床 `home/1`、钟 `meeting/32`、工作站 `1`、蜂巢/磁石/避雷针/传送门 `0`）。床只认 `part=head`。范围外记录原样保留。只有 POI 容器形状坏才整块按方块重建；0 字节 POI 文件按空区域重建，没东西可补就删文件。删光了就删掉这个 POI 区块；文件空了就删文件。
7. **实体。** 单条实体缺 `id`/`UUID`/`Pos` 或不是 compound 时只删这一条；`Position`/`DataVersion`/`Entities` 容器坏才整块删。范围内 UUID 重复时，留下先出现的，删掉后面的。坏记录删光就删掉整块实体。
8. **POI/实体与 region 对齐。** `region/` 里没有的区块，`poi/`、`entities/` 里同一格的块删掉；**不新建 region**。如果 region 文件本身是 0 字节，会在其它阶段读它之前先删掉，再按“这个 region 没有区块”处理，避免留下孤儿 POI/实体。
9. **区域文件。** 这次碰到的 `region/`、`poi/`、`entities/`：0 字节文件直接删；表头已经空了就删文件，还剩区块的就按顺序压紧（去掉空洞）。

fixer 各阶段在终端（stderr 是 tty）画进度条。

**坏数据分两类。** 文件级读不出来/写不进去（权限、IO 错、目录冒充文件、截断到读不出头部）：只打日志，单列 `IO跳过`，不改文件、不当成空区域。文件能读但区块 NBT/结构坏：`fixer` 按最小单位删（单条刻/POI/实体记录、Y 坏子区块，只有区块级 NBT 坏才整块），`merge` 整块安全跳过，都不写半份数据。压缩类型本库不认识（例如 LZ4 type 4、mcc）只记日志、跳过，不按坏块删。

`fixer` 最后一行会打印：删区块（含 `坏NBT`）、补 `InhabitedTime`、光照/高度、计划刻删/坏记录/重复、POI 删/补/重复/坏记录/坏块/块/文件、实体删/坏记录/块/文件、改坐标/重复段/Y坏段/压调色板、删空 MCA/format、`IO跳过`、失败。失败非 0 时进程返回非 0；`IO跳过` 只记录，不算处理失败。`merge` 会打印搬运方块数、计划刻/实体/POI、跳过区块和坏区域/坏实体/坏POI/存盘失败。

## 规则插件在判什么

当前文件是 `rules.so.26.1.1`。换一套同 ABI 的插件：`ln -sf 别的.so rules.so`，不用重编 `fixer`。自己写插件的接口在 `rules.hpp`，必须用同一套 g++ / libstdc++ 编。兼容性看 `RULES_ABI` **和** `sizeof(Rules_Api)`；改了接口就把 `RULES_ABI` 加 1，旧插件会装不上。当前 ABI 是 NBR4（`0x4e425234`），新增了 POI 默认表 `Poi_Info` / `poi_Get`。

规则只看这一格和六个面，不再去读斜下方。拿不准就留着：**宁可漏拆，不拆玩家搭的东西。** 插件只能把东西变少（拆掉，或把 `true` 面改成 `false`，或换成一个规则表不再管的方块），否则 `fixer` 可能停不下来。

26.1.1 这版和旧规则相比，使用时要注意：

- **支撑按面算。** 上半砖只有顶面算实心，下半砖只有底面算；楼梯、活板门同样。以前上半砖和下半砖被当成“上下都能撑”，会误拆或漏拆。
- **重力方块只按指定规则拆。** 沙子、红沙、沙砾、可疑沙/可疑沙砾、铁砧（含破损）、龙蛋，只有正下方是**空气、`minecraft:water`、`minecraft:lava`、火/灵魂火**时拆掉，**不生成掉落物**。下面是雪、草、藤蔓等其它可替换方块或任何其它方块时都保留；含水方块不算“水”。这是故意和原版 `isFree` 不同，宁可漏拆。
- **混凝土粉末**先看四周有没有能碰到的水，有就变成对应的混凝土；没有才按上面的重力规则判。
- **霜冰**一律换成水（冰霜行者刚踩出来、还没化的也会被化掉）。
- **落叶层**按 25w06a 后的规则，顶面中心支撑即可（栅栏、墙、锁链也认）；**雪层**要求下面顶面完整，开着的活板门/漏斗不再算。
- **龟蛋可以撑住挂在它下面的灯笼**；`copper_lantern` 归薄片（不能反过来撑火把）。附生西瓜/南瓜茎只认 farmland。
- **村民工作站、床、蜂箱、磁石、炼药锅这类兴趣点方块**没有“没支撑就会掉”的依据，悬空也留着；缺失的 POI 记录会按 `rules` 的默认表补。钟除外，它按挂法检查，墙钟只认贴着的那一面。
- **中低优先级 Wiki 差异已按 26.1.1 收**：发光地衣/幽匿脉络和紫水晶要求完整面，紫水晶不能长在树叶/蜂蜜块上；压力板不能放在树叶/TNT 上；栅栏门不再提供中心支撑；脚手架 `distance=7` 且下方没支撑会删；海带要求下方完整顶面（漏斗等不算）。
- **紫颂植株**看不到斜下方那一格的根，横枝一律留着。末地的树不会因为这条被成片拆掉，极少数本来该塌的无根横枝也会留下。

## nbtrw：看一眼存档，不改它

这是库的 demo，不是修图程序。参数都要写全，没有默认路径。

```sh
./nbtrw nbt   <file.nbt>                       # 打印成 SNBT
./nbtrw nbtw  <file.nbt>                       # 读、编码、再解析，核对编码/深拷贝/比较（不回写）
./nbtrw dat   <level.dat>                      # 读 level.dat
./nbtrw mca   <目录> <rx> <rz> <cx> <cz> [w]   # 读区域里的一个区块；w 会另存 .mca_test.mca
./nbtrw chunk <file.nbt> <x> <y> <z> [方块名]  # 读单区块文件里的一格
./nbtrw level <存档目录>                       # 看 DataVersion、三个维度的区域目录、(0,0) 在不在
```

`level` 适合先确认目录认没认错。维度目录按 DataVersion 选：大于等于 4774 用 `dimensions/minecraft/<维度>/`，否则用老的 `region/`、`DIM-1/`、`DIM1/`。

要在自己的程序里用这个库，包含 `nbtrw.hpp`，链接 `-lnbtrw -lz`。

## 它不做什么

- 不升级方块 id，不搬玩家存档、计分板、进度。版本对齐靠游戏的“优化世界”。
- 不模拟原版全部物理。树叶腐烂、珊瑚缺水、冰自然融化、甘蔗旁边要有水，这些不做。重力方块和霜冰是上面列过的例外。
- POI 只按 `rules` 的表补 vanilla 方块；不猜 mod 的 POI 类型，也不重算已有合法记录的票数。范围外记录不动。
- 不碰读不出来的区域文件；文件能读但区块 NBT/结构坏的，fixer 整块删、merge 整块跳过。
- 不管你在 `fixer` 之后又跑了一次 `merge`。
